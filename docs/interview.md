> 这是一个基于 FastAPI 和 LangGraph 思想构建的企业级智能运维 Agent。它能理解运维人员的自然语言问题，自主规划排查步骤、调用日志/监控/数据库/RAG 等工具收集证据，完成故障根因分析并生成报告；同时具备人工审批、RBAC 权限和操作审计等企业特性。我重点做了工具注册中心、有状态图编排、可降级设计和可评测体系。

## 二、核心设计问题（高频）

### Q1：为什么用 LangGraph 而不是直接写 if-else 流程？
固定流程（if-else）适用于步骤确定的场景；但 Agent 的特点是**下一步动作依赖上一步结果**，且需要循环（工具结果不够继续调）、条件分支（是否需审批）、中断（等人工）。LangGraph 用「状态 + 节点 + 条件边 + 循环」显式建模这类流程。我的项目里用自研轻量图引擎实现了同样语义（为了零依赖可跑），并在 `graph.py` 的 `build_langgraph()` 留了迁移路径。

### Q2：为什么 agent_steps 和 tool_executions 分两张表？
- `agent_steps` 记录 Agent 的**工作流节点**（规划、分析、报告）——回答"Agent 在想什么"。
- `tool_executions` 记录**具体工具调用**（名字、参数、结果、耗时）——回答"Agent 做了什么"。
分开才能做可解释性：出问题时能回溯"因为哪个工具的什么证据，得出什么结论"。

### Q3：为什么用 JSONB / JSON 存输入输出？
不同工具的输入输出结构差异很大（日志是数组、监控是对象、数据库是指标）。用 JSON/JSONB 既灵活又能保留结构；PostgreSQL 的 JSONB 还支持 GIN 索引和 JSON 查询。

### Q4：怎么保证 Agent 不会盲目调用所有工具？
Planner 根据问题语义选工具：HTTP 500 → 日志优先；服务宕机 → 监控优先；连接超时 → 数据库诊断；历史方案 → RAG。这是 Agent 与固定流程的本质区别。评测里工具选择准确率 99%。

### Q5：工具调用的本质是什么？
**不是大模型直接操作数据库**，而是：模型负责"选择和推理"→ 输出工具名和参数 → 后端程序真正执行工具 → 结果回传给模型继续推理。我的 `ToolRegistry.execute` 集中做了参数校验、超时、重试、执行记录。

### Q6：RAG 的完整链路？
文档 → 加载(PDF/文本) → 切片(chunk_size=600, overlap=80，避免答案被切断) → Embedding 向量化 → 存库 → 查询向量化 → 余弦相似度检索 → Top-K 作为证据注入。overlap 的作用是保留跨切片上下文。

### Q7：为什么向量维度不能随意指定？
必须与 Embedding 模型输出维度一致，否则检索时向量空间不匹配、相似度无意义。我用配置 `EMBEDDING_DIM` 统一管理，并在注释里提醒换模型要重新向量化全库。

### Q8：高风险操作怎么防篡改？
审批时记录 `arguments_signature`（参数 SHA256 签名）。执行前后端重新比对签名，不一致直接拒绝——防止 Agent 在审批通过后偷偷改参数。审批还校验：审批人角色权限、是否重复审批、审批是否仍有效。

### Q9：为什么要做降级设计？
生产环境 LLM/向量模型/数据库可能不可用。把外部依赖抽象成统一接口，核心流程不因外部故障中断——这是成熟度体现。面试可讲："我实现了模型可插拔和环境自适应"。

### Q10：怎么评测 Agent 效果，而不是只展示几次成功对话？
建了 32 个故障测试集，每个标注期望工具和期望关键词，用脚本统计工具选择准确率、结论命中率、响应时间。实测 99% / 85.9% / 70ms。这样才能量化能力、发现短板（我先测出关键词命中率只有 51.6%，改进 analyzer 汇总全部证据后提升到 85.9%）。

## 三、简历项目描述（实测后可用）

**OpsPilot AI — 企业级智能 IT 运维 Agent 平台**
*Python / FastAPI / LangGraph / RAG / PostgreSQL / Redis / Vue 3 / Docker*

- 基于 LangGraph 有状态图编排思想，实现任务规划、工具路由、故障分析、人工审批与报告生成的完整 Agent 工作流，支持条件分支、循环与工具失败重试。
- 设计工具注册中心与风险分级机制，通过 Function Calling 接入日志查询、监控指标、数据库诊断等 7 类工具，实现多步骤自主调用与执行留痕。
- 构建 RAG 运维知识库，实现文档解析、文本切片、Embedding 向量化与相似度检索，为诊断提供历史 Runbook 证据。
- 实现 JWT + RBAC 三级权限与高风险操作人工审批，通过参数签名校验防止审批后参数篡改，并记录完整审计日志。
- 设计双栈可降级架构（LLM/数据库/向量均可切换），保证无外部依赖环境下全功能可演示。
- 建立 32 例故障测试集与评测脚本，实测工具选择准确率 99%、诊断结论关键词命中率 85.9%、平均响应 70ms。

> 注意：以上数据来自本项目真实评测（`tests/eval_report.json`），可放心使用。

## 四、可能的追问与回答要点

- **"你用的 LangGraph 是哪个版本？"** → 诚实说明：核心用自研轻量图引擎实现同等语义（零依赖可跑），代码中保留了 LangGraph 的 StateGraph 迁移路径；如果装了 langgraph 可直接切换。
- **"为什么前端不用 Vue3？"** → 控制台用原生 JS 单文件是为了零构建、双击即跑、便于演示；数据交互（SSE、REST）与框架无关，真实 Vue3 项目结构可按 `frontend/src` 组织（Dashboard/AgentChat/Knowledge/Incidents/Traces）。
- **"LLM 幻觉调出不存在的工具怎么办？"** → Planner 之后有 `valid = [c for c in tool_calls if registry.get(c.name)]` 过滤，只允许已注册工具执行。
- **"工具超时怎么办？"** → `ToolRegistry.execute` 用 `asyncio.wait_for` 做超时控制 + 指数退避重试，失败记录到 tool_executions。
