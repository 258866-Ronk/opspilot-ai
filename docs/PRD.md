# OpsPilot AI 产品需求文档（PRD）

## 1. 背景
企业拥有多个 Java 微服务（用户/订单/商品/支付/网关）。故障发生时运维人员需登录多个平台、查指标、翻日志、找历史记录、建工单、通知负责人，流程繁琐。本平台用 Agent 串联这些步骤。

## 2. 核心场景
运维输入："今天下午订单服务出现大量 HTTP 500 错误，帮我分析原因并给出处理建议。"
Agent 执行：任务规划 → 监控查询 → 日志检索 → 数据库诊断 → RAG 检索 → 证据整合 → 根因分析 → 人工审批 → 报告生成。

## 3. 功能模块

| 模块 | 功能 | 优先级 | 实现状态 |
|---|---|---|---|
| 运维监控 | 服务状态、指标展示 | P0 | ✅ |
| 日志管理 | 日志查询、错误分析 | P0 | ✅ |
| RAG 知识库 | 上传、解析、切片、检索 | P0 | ✅ |
| Agent 核心 | 任务规划、工具调用、状态管理 | P0 | ✅ |
| 执行追踪 | 轨迹、耗时、评测 | P0 | ✅ |
| 用户管理 | 注册、登录、角色权限 | P1 | ✅ |
| 故障工单 | 创建、查询、更新 | P1 | ✅ |
| 人工审批 | 高风险操作审批 | P1 | ✅ |

## 4. 用户角色
- 普通运维员：发起分析、查看报告
- 运维负责人：审批高风险操作、管理工单
- 系统管理员：管理用户、知识库、工具权限

## 5. 非功能需求
- 安全性：工具权限控制；第一版全用模拟数据，不连生产环境
- 可追踪：记录每次执行过程
- 稳定性：工具超时与重试
- 可扩展性：可增加新工具
- 可评测：测试集评价效果

## 6. 安全原则
所有运维数据均为模拟数据，不执行真实重启/删除/改库操作。高风险操作在系统中也只做模拟执行。
